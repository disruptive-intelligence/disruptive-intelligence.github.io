## Annexes opérationnelles


### Annexe A — Glossaire

| Terme | Définition |
|-------|-----------|
| **AitM** | Adversary-in-the-Middle — technique de phishing interceptant la communication entre la victime et le service légitime pour capturer les tokens de session, contournant le MFA |
| **APT** | Advanced Persistent Threat — acteur de menace sophistiqué, généralement étatique, caractérisé par sa persistance et ses ressources |
| **ASAT** | Anti-Satellite Weapon — arme anti-satellite, menace physique sur les systèmes spatiaux |
| **BEC** | Business Email Compromise — compromission de messagerie professionnelle pour détourner des virements ou voler des informations |
| **Beaconing** | Communication régulière et périodique entre un implant malveillant et son serveur de commande et contrôle |
| **Bulletproof hosting** | Service d'hébergement résistant aux demandes de retrait des forces de l'ordre |
| **C2** | Command and Control — infrastructure utilisée par un attaquant pour communiquer avec les systèmes compromis |
| **CaaS** | Crime-as-a-Service — modèle économique où les capacités cybercriminelles sont vendues comme services |
| **ClickFix** | Technique de tromperie utilisant de fausses fenêtres d'erreur pour inciter l'utilisateur à exécuter un script malveillant |
| **COTS** | Commercial Off-The-Shelf — composants logiciels ou matériels commerciaux standard, non spécifiquement développés |
| **CRA** | Cyber Resilience Act — règlement européen sur la cybersécurité des produits numériques |
| **CTI** | Cyber Threat Intelligence — renseignement sur les cybermenaces |
| **CTL** | Cyber Threat Landscape — panorama du paysage de la cybermenace |
| **CVE** | Common Vulnerabilities and Exposures — système d'identification des vulnérabilités |
| **CVSS** | Common Vulnerability Scoring System — système de notation de la sévérité des vulnérabilités |
| **DDoS** | Distributed Denial of Service — attaque par déni de service distribué |
| **DLP** | Data Loss Prevention — solutions de prévention des fuites de données |
| **DORA** | Digital Operational Resilience Act — règlement européen sur la résilience numérique du secteur financier |
| **Dropper** | Programme malveillant dont la fonction est de déployer un autre malware sur le système cible |
| **EDR** | Endpoint Detection and Response — solution de détection et réponse sur les terminaux |
| **EMPACT** | European Multidisciplinary Platform Against Criminal Threats — cadre de coopération opérationnelle européen |
| **EPSS** | Exploit Prediction Scoring System — score de probabilité d'exploitation d'une vulnérabilité |
| **EUVD** | European Union Vulnerability Database — base de données européenne des vulnérabilités |
| **Faketivisme** | Opérations étatiques déguisées en hacktivisme pour le déni plausible |
| **IAB** | Initial Access Broker — courtier en accès initial, revendeur d'accès compromis |
| **ICS** | Industrial Control Systems — systèmes de contrôle industriel |
| **Infostealer** | Malware conçu pour voler des informations (credentials, cookies, tokens, données système) |
| **Intrusion set** | Ensemble cohérent d'activités malveillantes attribuées à un même acteur sur la base de TTPs communes |
| **IoA** | Indicator of Attack — indicateur comportemental signalant une attaque |
| **IoC** | Indicator of Compromise — indicateur technique signalant une compromission |
| **KEV** | Known Exploited Vulnerabilities — catalogue CISA des vulnérabilités activement exploitées |
| **LCA** | Level of Confidence in Assessment — niveau de confiance dans un jugement analytique |
| **Living-off-the-Land (LotL)** | Technique utilisant les outils natifs du système ciblé plutôt que des malwares déployés |
| **Loader** | Programme malveillant dont la fonction est de télécharger et exécuter un autre malware |
| **MAI** | Malicious Activity of Interest — activité malveillante satisfaisant les critères de pertinence (framework CERT-EU) |
| **MFA** | Multi-Factor Authentication — authentification multi-facteurs |
| **MISP** | Malware Information Sharing Platform — plateforme open source de partage de CTI |
| **MOA** | Mode Opératoire d'Attaque — terminologie ANSSI pour un ensemble d'intrusion |
| **NIS2** | Directive sur la sécurité des réseaux et systèmes d'information (version 2) |
| **OBC** | On-Board Computer — calculateur embarqué d'un satellite |
| **OBSW** | On-Board Software — logiciel embarqué d'un satellite |
| **OT** | Operational Technology — technologies opérationnelles contrôlant des processus physiques |
| **PAM** | Privileged Access Management — gestion des accès privilégiés |
| **PIR** | Priority Intelligence Requirement — besoin en renseignement prioritaire |
| **PSOA** | Private Sector Offensive Actor — acteur offensif du secteur privé (cyber-mercenaire) |
| **Quishing** | QR code phishing — phishing via QR codes malveillants |
| **RaaS** | Ransomware-as-a-Service — modèle économique de ransomware en tant que service |
| **RDP** | Remote Desktop Protocol — protocole de bureau à distance |
| **RMM** | Remote Monitoring and Management — outils de surveillance et gestion à distance |
| **RTOS** | Real-Time Operating System — système d'exploitation temps réel (contexte spatial) |
| **SBOM** | Software Bill of Materials — inventaire des composants logiciels d'un produit |
| **SCADA** | Supervisory Control and Data Acquisition — systèmes de contrôle et d'acquisition de données |
| **Slopsquatting** | Exploitation des hallucinations de LLMs en créant des packages malveillants portant les noms de packages fictifs recommandés par l'IA |
| **STIX** | Structured Threat Information eXpression — standard de représentation de la CTI |
| **Supply chain attack** | Attaque exploitant les relations de confiance entre une organisation et ses fournisseurs |
| **TAXII** | Trusted Automated Exchange of Intelligence Information — protocole d'échange de CTI |
| **TLP** | Traffic Light Protocol — protocole de classification des conditions de partage d'information |
| **TM/TC** | Telemetry/Telecommand — liaisons de télémétrie et télécommande satellite |
| **TTP** | Tactics, Techniques and Procedures — tactiques, techniques et procédures d'un acteur |
| **Vishing** | Voice phishing — phishing par appel téléphonique |
| **WEP** | Words of Estimative Probability — vocabulaire calibré de probabilité estimative |
| **Wiper** | Malware destructif conçu pour effacer les données de manière irréversible |
| **Zero trust** | Architecture de sécurité qui ne fait confiance à aucun utilisateur ou appareil par défaut |
| **Zero-day** | Vulnérabilité inconnue du vendeur et pour laquelle aucun correctif n'existe au moment de l'exploitation |

### Annexe E — Templates opérationnels

#### E.1 — Structure type d'un Cyber Threat Landscape Report

1. **Page de garde** : titre, auteur, date, classification (TLP), version, périmètre
2. **Executive summary** (1-2 pages) : principaux constats, menaces prioritaires, recommandations clés
3. **Méthodologie** (1 page) : périmètre, période, sources, frameworks, limites explicites
4. **Analyse par catégorie de menace** :
   - Menace étatique (par nexus : Chine, Russie, Iran, RPDC, autres)
   - Cybercriminalité (ransomware, infostealers, IAB, fraude)
   - Hacktivisme et menaces idéologiques
   - Menaces émergentes (IA, supply chain, OT)
5. **Analyse sectorielle** : menaces spécifiques au secteur de l'organisation
6. **Tendances et prospective** : évolutions à 12-24 mois
7. **Recommandations priorisées** : P0/P1/P2 avec justification fondée sur le CTL
8. **Annexes techniques** : IOCs, TTPs (mapping ATT&CK), références

#### E.2 — Template de briefing exécutif COMEX

1. **Conclusion d'abord** : les 3 menaces prioritaires en une phrase chacune
2. **Impact business** : pour chaque menace, quel impact concret sur l'organisation ?
3. **Incident marquant** : le cas le plus significatif de la période, en 5 lignes
4. **Posture** : où en est l'organisation par rapport aux menaces identifiées ?
5. **Actions** : les 5 actions prioritaires, avec coût estimatif et délai
6. **Question ouverte** : le sujet qui nécessite une décision du COMEX

#### E.3 — Grille d'évaluation des sources

| Critère | A | B | C | D | E | F |
|---------|---|---|---|---|---|---|
| Track record | Long, vérifié | Généralement bon | Variable | Problématique | Mauvais | Inconnu |
| Accès aux données | Direct | Intermédiaire | Indirect | Limité | Aucun | Inconnu |
| Biais connus | Documentés | Partiels | Significatifs | Forts | Graves | Inconnus |
| Corroboration | Systématique | Fréquente | Occasionnelle | Rare | Absente | N/A |

#### E.4 — Checklist de validation pré-publication

- [ ] Les PIR sont-ils tous adressés ?
- [ ] Les niveaux de confiance sont-ils explicites pour chaque assessment ?
- [ ] Les WEP sont-ils utilisés de manière cohérente ?
- [ ] Les biais de collecte sont-ils documentés ?
- [ ] Les hypothèses alternatives sont-elles considérées ?
- [ ] Les sources sont-elles citées ou référencées ?
- [ ] Le TLP est-il approprié ?
- [ ] La revue par les pairs est-elle complète ?
- [ ] Les recommandations sont-elles fondées sur le CTL (pas génériques) ?
- [ ] Le document est-il exploitable par l'audience cible ?

> **Note finale**
>
> Ce cours a été conçu comme un document autonome, exploitable par un praticien, fondé exclusivement sur les productions 2025-2026 des principales autorités mondiales en matière de cybermenace. Il reflète l'état de l'art au moment de sa rédaction et doit être traité comme un corpus vivant — les menaces évoluent, les réglementations se transposent, les acteurs s'adaptent. La mise à jour régulière des analyses, des recommandations et des données factuelles est une responsabilité permanente du praticien.
